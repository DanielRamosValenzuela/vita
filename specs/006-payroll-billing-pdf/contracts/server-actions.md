## 2. Payroll Generation

### `generatePayrollAction`

**Location**: `src/features/admin-hr/api/payroll-actions.ts`
**Auth**: `requireAdminHRWithOrg`

**Input**:
```typescript
{
  month: number    // 1-12
  year: number     // e.g. 2026
  force?: boolean  // true to overwrite existing period
}
```

**Output**: `ActionResult<{ periodId: string; documentsGenerated: number; totalAmount: number; errors: string[] }>`

**Validation (Zod)**:
- `month`: integer, min 1, max 12
- `year`: integer, min 2020, max current year + 1
- Period must be in the past (month/year < current month/year)
- If period already exists and `force` is false, return error suggesting confirmation

**Behavior**:
1. Check if PayrollPeriod exists for (org, month, year).
2. If exists and !force → return error with existing period info.
3. If exists and force → delete existing period + documents + storage files.
4. Create PayrollPeriod (status: GENERATING).
5. Fetch all users with active contracts in org for the period.
6. For each user: calculate payments, generate PDF, upload, create PayrollDocument.
7. Update PayrollPeriod with totals and status.
8. Return summary.

## 3. Payroll History & Download

### `getPayrollPeriodsAction`

**Location**: `src/features/payroll/api/payroll-history-actions.ts`
**Auth**: Any authenticated user with org

**Input**:
```typescript
{
  year?: number  // Filter by year, default current year
}
```

**Output**: `ActionResult<PayrollPeriodSummary[]>`

```typescript
type PayrollPeriodSummary = {
  id: string
  month: number
  year: number
  status: PayrollPeriodStatus
  totalDocuments: number
  totalAmount: number
  currency: Currency
  generatedAt: DateTime | null
  isAutoGenerated: boolean
}
```

**Role-based filtering**:
- ADMIN_HR: all periods for org.
- CHIEF_AREA: all periods for org (filter documents at document level).
- STAFF: all periods for org (filter documents at document level).

```typescript

}
```

## 4. Payment Calculation

### `calculateShiftPaymentAction`

**Location**: `src/features/shifts/api/shift-payment-actions.ts`
**Auth**: Internal (called from shift completion flow)

**Input**:
```typescript
{
  shiftId: string
}
```

**Output**: `ActionResult<{ paymentId: string; finalAmount: number }>`

**Behavior**:
1. Fetch shift with contract → rateTemplate → components.
2. Fetch calendar day multiplier for shift date.
3. Filter applicable components by applyCondition and shift context.
4. Calculate each component: PER_SHIFT (fixed), PER_MINUTE (value × minutes), PER_HOUR (value × hours), etc.
5. Sum → baseAmount.
6. Apply contract.customMultiplier → totalAmount.
7. Apply calendarMultiplier → finalAmount.
8. Create ShiftPayment (status: CALCULATED) + ShiftPaymentBreakdown records.
