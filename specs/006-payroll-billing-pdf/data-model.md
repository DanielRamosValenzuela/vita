# Data Model: Payroll Billing PDF Generation

**Feature Branch**: `006-payroll-billing-pdf`
**Date**: 2026-03-03

## New Entities

### PayrollPeriod

Represents a monthly billing cycle for an organization.

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| id | String (cuid) | Yes | auto | Primary key |
| organizationId | String (FK → Organization) | Yes | — | Multi-tenant isolation |
| month | Int | Yes | — | Month number (1-12) |
| year | Int | Yes | — | Year (e.g. 2026) |
| status | PayrollPeriodStatus | Yes | GENERATING | Current state |
| generatedBy | String (FK → User) | No | null | User who triggered (null if auto) |
| generatedAt | DateTime | No | null | When generation completed |
| totalDocuments | Int | Yes | 0 | Count of documents generated |
| totalAmount | Float | Yes | 0 | Sum of all document amounts |
| currency | Currency | Yes | — | From organization.currency |
| errorLog | String | No | null | Errors during generation (JSON) |
| isAutoGenerated | Boolean | Yes | false | True if triggered by cron |
| createdAt | DateTime | Yes | now() | — |
| updatedAt | DateTime | Yes | auto | — |

**Unique constraint**: `(organizationId, month, year)`

**Indexes**: `[organizationId]`, `[organizationId, year]`, `[status]`

**States (PayrollPeriodStatus)**:
```
GENERATING → COMPLETED
GENERATING → COMPLETED_WITH_ERRORS
GENERATING → FAILED
```

- `GENERATING`: Generation in progress (prevents concurrent runs).
- `COMPLETED`: All documents generated successfully.
- `COMPLETED_WITH_ERRORS`: Some documents generated, some failed.
- `FAILED`: Generation completely failed.

**Relations**:
- `organization` → Organization (many-to-one)
- `generatedByUser` → User (many-to-one, optional)
- `documents` → PayrollDocument[] (one-to-many)

### PayrollDocument

Individual payroll document per staff member per period.

| Field | Type | Required | Default | Description |
|-------|------|----------|---------|-------------|
| id | String (cuid) | Yes | auto | Primary key |
| payrollPeriodId | String (FK → PayrollPeriod) | Yes | — | Parent period |
| userId | String (FK → User) | Yes | — | Staff member |
| organizationId | String (FK → Organization) | Yes | — | Multi-tenant (denormalized for query perf) |
| totalAmount | Float | Yes | — | Total payment for this staff this period |
| baseSalaryAmount | Float | Yes | 0 | Prorated base salary portion |
| shiftsAmount | Float | Yes | 0 | Sum of all shift payments |
| monthlyComponentsAmount | Float | Yes | 0 | Sum of monthly fixed components |
| currency | Currency | Yes | — | From organization.currency |
| shiftsCount | Int | Yes | 0 | Number of shifts included |
| contractDaysInPeriod | Int | Yes | — | Days the contract was active in period |
| totalDaysInPeriod | Int | Yes | — | Total days in the billing period |
| storagePath | String | Yes | — | Path in Supabase Storage bucket |
| fileName | String | Yes | — | Display filename (e.g. "nomina-2026-01-juan-perez.pdf") |
| generatedAt | DateTime | Yes | now() | When document was generated |
| createdAt | DateTime | Yes | now() | — |
| updatedAt | DateTime | Yes | auto | — |

**Unique constraint**: `(payrollPeriodId, userId)`

**Indexes**: `[payrollPeriodId]`, `[userId]`, `[organizationId]`, `[organizationId, userId]`

**Relations**:
- `payrollPeriod` → PayrollPeriod (many-to-one)
- `user` → User (many-to-one)
- `organization` → Organization (many-to-one)

## Existing Entities Used (No Changes)

### ShiftPayment (existing, lines 608-632 in schema.prisma)

Used as-is for per-shift payment calculation. Key fields:
- `shiftId` (unique, FK → Shift)
- `totalAmount`, `baseAmount`, `calendarMultiplier`, `finalAmount`
- `minutesWorked`, `isPartialCompletion`
- `status` (PENDING → CALCULATED → APPROVED → PAID / DISPUTED)
- `breakdowns` → ShiftPaymentBreakdown[]

### ShiftPaymentBreakdown (existing, lines 634-650 in schema.prisma)

Component-level detail for each shift payment. Key fields:
- `shiftPaymentId` (FK → ShiftPayment)
- `componentId` (FK → RateComponent)
- `componentName`, `componentType`
- `baseValue`, `calculatedValue`, `appliedMinutes`

### Contract (existing, lines 312-337 in schema.prisma)

Links user to rate template. Key fields for payroll:
- `userId`, `organizationId`, `areaId`, `rateTemplateId`
- `customMultiplier` (personal multiplier, e.g. 1.2x)
- `startDate`, `endDate`, `isActive`

### RateTemplate + RateComponent (existing)

Tariff structure. RateComponent fields critical for calculation:
- `type` (ComponentType enum: BASE_SALARY, PER_SHIFT, PER_MINUTE, etc.)
- `value` (monetary amount)
- `unit` (ComponentUnit: MONTHLY, PER_SHIFT, PER_MINUTE, etc.)
- `applyCondition` (ALWAYS, WEEKDAY_ONLY, WEEKEND_ONLY, HOLIDAY_ONLY, etc.)
- `extraOnly` (overtime-only flag)

### OrganizationCalendar (existing)

Calendar day types with multipliers. Key fields:
- `organizationId`, `date` (unique together)
- `type` (DayType: NORMAL, HOLIDAY, IRRENUNCIABLE, etc.)
- `multiplier` (Float, default 1.0)

## Data Flow for Payroll Generation

```
1. TRIGGER: Manual (ADMIN_HR) or Automatic (pg_cron)
   │
2. CREATE PayrollPeriod (status: GENERATING)
   │
3. FOR EACH User with active Contract in org:
   │
   ├─ 3a. Calculate prorated BASE_SALARY
   │       contract days in period / total period days × monthly base
   │
   ├─ 3b. Fetch Shifts (COMPLETED) in period with ShiftPayments
   │       Sum all ShiftPayment.finalAmount
   │
   ├─ 3c. Calculate monthly fixed components (unit = MONTHLY)
   │       Prorated same as base salary
   │
   ├─ 3d. Total = baseSalary + shiftsAmount + monthlyComponents
   │
   ├─ 3e. IF total > 0:
   │       Generate PDF → Upload to Storage → Create PayrollDocument
   │
   └─ 3f. IF total = 0:
           Skip (no document created)
   │
4. UPDATE PayrollPeriod (status: COMPLETED / COMPLETED_WITH_ERRORS)
   │
5. CREATE Notification for ADMIN_HR
```
